# Product Requirements Document
## MailTrace — Agentic AI for Email & DNS Diagnosis

**Built for:** Kanz AI Hackathon Submission
**Timeline:** 2-day build (working prototype)
**Author:** Ibrahim Ismail

---

## 1. Overview & Purpose

MailTrace is an agentic AI diagnostic tool that takes a plain-language description of an email delivery problem and autonomously reasons through the likely technical causes — the same way an experienced IT support engineer would. Instead of just tracking a ticket or searching a knowledge base for similar past issues, it performs **live, real DNS lookups**, forms hypotheses, rules them out one at a time, and shows its full reasoning trace to the user.

**The core differentiator:** most "AI support tools" either (a) route/categorize tickets for a human to diagnose, or (b) run a fixed checklist of every possible check regardless of the symptom. MailTrace is **symptom-driven** — the AI decides *which* checks matter based on what the user actually described, and reasons step-by-step in a visible, transparent trace, using REAL DNS data (not simulated/mocked results).

---

## 2. Core User Flow

1. User lands on a single-page app with a text input: *"Describe your email problem"*
2. User types a plain-language symptom (e.g., "Our emails are going to spam" or "Customers say our emails aren't arriving")
3. User enters the domain to diagnose (e.g., `rainbreezes.com`)
4. User clicks "Diagnose"
5. A reasoning trace panel appears and fills in **live, step by step** (not all at once):
   - Shows the AI's initial hypothesis list
   - Shows each check as it runs ("🔍 Checking MX record...")
   - Shows the real result returned
   - Shows the AI's interpretation of that result (ruling in/out causes)
   - Repeats until resolved or all relevant hypotheses are exhausted
6. Final summary card appears: **Diagnosis** + **Recommended Fix**
7. Full trace remains visible/scrollable below for transparency

## 3. Technical Architecture

### 3.1 Stack
- **Frontend:** React (Replit's default React template is fine) — single page, no routing needed
- **Backend:** Node.js + Express (same repl, or Replit's fullstack template)
- **AI:** Claude API (Anthropic) — used for the reasoning/hypothesis logic only, NOT for DNS lookups
- **DNS Lookups:** Node.js built-in `dns` module (`dns.promises`) — no external API key required, fully real, fully free

### 3.2 High-Level Flow

```
Frontend (React)
   → sends { symptom, domain } to backend
Backend (Express)
   → orchestrates the reasoning loop (see Section 4)
   → calls real DNS check functions
   → calls Claude API for interpretation/next-step decisions
   → streams trace steps back to frontend (or returns full trace array)
Frontend
   → renders trace steps progressively (simulate streaming if true streaming is too complex for the timeline)
```

### 3.3 DNS Check Functions (write these FIRST — pure Node.js, no AI needed, testable independently)

Create a file `dnsChecks.js` with these functions. Each returns a structured object, not just raw data:

```javascript
const dns = require('dns').promises;

async function checkMX(domain) {
  try {
    const records = await dns.resolveMx(domain);
    return {
      check: 'MX',
      success: true,
      found: records.length > 0,
      data: records, // array of {exchange, priority}
      raw: JSON.stringify(records)
    };
  } catch (err) {
    return { check: 'MX', success: false, found: false, error: err.code, raw: err.message };
  }
}

async function checkSPF(domain) {
  try {
    const records = await dns.resolveTxt(domain);
    const spfRecord = records.find(r => r.join('').startsWith('v=spf1'));
    if (!spfRecord) {
      return { check: 'SPF', success: true, found: false, data: null };
    }
    const spfString = spfRecord.join('');
    // Count DNS lookups within SPF (include:, a:, mx:, ptr:, exists: each count as 1 lookup, max 10 allowed per RFC 7208)
    const lookupMechanisms = (spfString.match(/include:|a:|mx:|ptr:|exists:/g) || []).length;
    return {
      check: 'SPF',
      success: true,
      found: true,
      data: spfString,
      lookupCount: lookupMechanisms,
      exceedsLimit: lookupMechanisms > 10,
      hardFail: spfString.includes('-all'),
      softFail: spfString.includes('~all')
    };
  } catch (err) {
    return { check: 'SPF', success: false, found: false, error: err.code, raw: err.message };
  }
}

async function checkDKIM(domain, selectors = ['selector1', 'selector2', 'google', 'default', 'k1']) {
  const results = [];
  for (const selector of selectors) {
    try {
      const records = await dns.resolveTxt(`${selector}._domainkey.${domain}`);
      results.push({ selector, found: true, data: records.join('') });
    } catch (err) {
      results.push({ selector, found: false, error: err.code });
    }
  }
  const anyFound = results.some(r => r.found);
  return { check: 'DKIM', success: true, found: anyFound, selectorResults: results };
}

async function checkDMARC(domain) {
  try {
    const records = await dns.resolveTxt(`_dmarc.${domain}`);
    const dmarcRecord = records.find(r => r.join('').startsWith('v=DMARC1'));
    if (!dmarcRecord) {
      return { check: 'DMARC', success: true, found: false, data: null };
    }
    const dmarcString = dmarcRecord.join('');
    const policyMatch = dmarcString.match(/p=(\w+)/);
    return {
      check: 'DMARC',
      success: true,
      found: true,
      data: dmarcString,
      policy: policyMatch ? policyMatch[1] : 'unknown' // none, quarantine, reject
    };
  } catch (err) {
    return { check: 'DMARC', success: false, found: false, error: err.code, raw: err.message };
  }
}

module.exports = { checkMX, checkSPF, checkDKIM, checkDMARC };
```

**IMPORTANT:** Test each of these functions independently against `rainbreezes.com` (should return real, mostly-healthy results since that domain is genuinely configured) and against a domain with no email setup (like a random unused domain) to confirm both "found" and "not found" paths work correctly before moving to the reasoning layer.

### 3.4 The Reasoning Loop (the "agentic" core — build this SECOND)

Create `reasoningAgent.js`. This orchestrates calls to Claude, deciding what to check next and interpreting results.

**Design principle:** Do NOT send one giant prompt asking Claude to "diagnose everything." Instead, use a loop:

```javascript
const Anthropic = require('@anthropic-ai/sdk');
const { checkMX, checkSPF, checkDKIM, checkDMARC } = require('./dnsChecks');

const anthropic = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

const AVAILABLE_CHECKS = {
  MX: checkMX,
  SPF: checkSPF,
  DKIM: checkDKIM,
  DMARC: checkDMARC
};

async function runDiagnosis(symptom, domain, onStep) {
  // onStep is a callback to push trace updates to the frontend as they happen
  const trace = [];
  const completedChecks = {};

  // STEP 1: Get initial hypothesis + first check to run
  let systemPrompt = `You are an expert email/DNS diagnostic engineer, similar to a senior IT support engineer troubleshooting mail flow issues. 
You have access to these DNS checks: MX, SPF, DKIM, DMARC.
Given a user's symptom description, you reason step-by-step like a real engineer:
1. Form a hypothesis list of likely causes
2. Decide which ONE check to run next (most diagnostic value first — usually MX first, since if mail isn't routing at all, nothing else matters)
3. After each result, interpret it and rule in/out causes
4. Continue until you reach a diagnosis or have run all relevant checks

Respond ONLY in this JSON format at each step:
{
  "reasoning": "brief explanation of your thinking",
  "hypotheses": ["list", "of", "current", "possible", "causes"],
  "nextCheck": "MX" | "SPF" | "DKIM" | "DMARC" | null,
  "diagnosis": null | "final diagnosis text if you have reached a conclusion",
  "recommendation": null | "fix recommendation if diagnosis is set"
}
Set nextCheck to null ONLY when you have either reached a diagnosis or genuinely exhausted useful checks.`;

  let conversationHistory = [
    { role: 'user', content: `Symptom: "${symptom}"\nDomain: ${domain}\n\nBegin your diagnostic reasoning.` }
  ];

  let maxSteps = 6; // safety limit — prevents infinite loops, per research on agent coherence degrading past ~10 steps
  let stepCount = 0;

  while (stepCount < maxSteps) {
    stepCount++;

    const response = await anthropic.messages.create({
      model: 'claude-sonnet-4-5',
      max_tokens: 1024,
      system: systemPrompt,
      messages: conversationHistory
    });

    const responseText = response.content[0].text;
    let parsed;
    try {
      parsed = JSON.parse(responseText);
    } catch (e) {
      // If Claude didn't return clean JSON, log and break gracefully
      trace.push({ type: 'error', message: 'Failed to parse AI response', raw: responseText });
      break;
    }

    trace.push({ type: 'reasoning', ...parsed, step: stepCount });
    if (onStep) onStep(trace[trace.length - 1]); // push to frontend live

    // If diagnosis reached, stop
    if (parsed.diagnosis) {
      break;
    }

    // If no next check decided, stop
    if (!parsed.nextCheck || !AVAILABLE_CHECKS[parsed.nextCheck]) {
      break;
    }

    // Run the actual DNS check
    const checkFn = AVAILABLE_CHECKS[parsed.nextCheck];
    const checkResult = parsed.nextCheck === 'DKIM' 
      ? await checkFn(domain) 
      : await checkFn(domain);
    completedChecks[parsed.nextCheck] = checkResult;

    trace.push({ type: 'check_result', check: parsed.nextCheck, result: checkResult, step: stepCount });
    if (onStep) onStep(trace[trace.length - 1]);

    // Add this exchange to conversation history so Claude has full context for next iteration
    conversationHistory.push({ role: 'assistant', content: responseText });
    conversationHistory.push({ 
      role: 'user', 
      content: `Result of ${parsed.nextCheck} check: ${JSON.stringify(checkResult)}\n\nContinue your reasoning. Interpret this result, update your hypotheses, and decide the next step.` 
    });
  }

  return trace;
}

module.exports = { runDiagnosis };
```

### 3.5 Backend API Endpoint (`server.js` or `index.js`)

```javascript
const express = require('express');
const cors = require('cors');
const { runDiagnosis } = require('./reasoningAgent');

const app = express();
app.use(cors());
app.use(express.json());

app.post('/api/diagnose', async (req, res) => {
  const { symptom, domain } = req.body;
  if (!symptom || !domain) {
    return res.status(400).json({ error: 'symptom and domain are required' });
  }

  try {
    // Simple approach: run full diagnosis, return complete trace at once
    // (Streaming/SSE is a nice-to-have if time allows, not required for MVP)
    const trace = await runDiagnosis(symptom, domain);
    res.json({ trace });
  } catch (err) {
    console.error(err);
    res.status(500).json({ error: 'Diagnosis failed', details: err.message });
  }
});

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => console.log(`Server running on port ${PORT}`));
```

### 3.6 Frontend Requirements

**Single page, simple layout:**

- Header: "MailTrace — AI Email & DNS Diagnostic Agent"
- Input section: text input for symptom, text input for domain, "Diagnose" button
- Results section (appears after clicking Diagnose):
  - Loading state while waiting for backend response
  - Render the `trace` array returned from the API, in order:
    - `type: 'reasoning'` entries → show as a card with the AI's reasoning text + current hypothesis list (styled distinctly, e.g., light blue background, a "🤔" or brain icon)
    - `type: 'check_result'` entries → show as a card with which check ran + the real result (styled distinctly, e.g., "🔍" icon, show raw DNS data in a monospace font for authenticity)
  - Final diagnosis (when `diagnosis` is non-null in the last reasoning entry) → show as a prominent highlighted summary card with the recommendation

**Styling:** Keep it clean and professional — this is for a hackathon demo screenshot/video, so it should look polished but doesn't need to be elaborate. Navy/teal color scheme is fine (matches professional IT/security tooling aesthetics). Monospace font for DNS data specifically helps it "read" as real technical output, not generic AI chat text.

**IMPORTANT UX detail:** Even if true real-time streaming (SSE/WebSockets) is too complex for the 2-day timeline, SIMULATE progressive reveal on the frontend — receive the full trace array from the backend, then reveal each trace entry with a short delay (e.g., 800ms-1200ms between entries) using `setTimeout` or similar. This preserves the "watching it think" demo effect without needing real streaming infrastructure.

## 8. Success Criteria

The build is "done enough to submit" when:
1. A user can type a real symptom + real domain and get a genuine, non-hallucinated diagnosis based on real DNS data
2. The reasoning trace is visible and readable, showing hypothesis → check → interpretation → next step
3. It works end-to-end without crashing on at least 3 different test domains
4. It looks clean enough to screenshot and record without embarrassment

Do not over-engineer beyond this. Working and demo-able beats feature-complete, given the timeline.
